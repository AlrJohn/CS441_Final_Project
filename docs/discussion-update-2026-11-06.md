For this update, I focused on connecting the search algorithms to our Wi-Fi planner so that it can choose access-point settings automatically. The greedy baseline starts with every AP at its highest setting and lowers settings when all devices can still receive service. I also added simulated annealing, which occasionally accepts a configuration that uses more energy so that the search can explore other possibilities (Kirkpatrick et al., 1983). For the recovery version, each candidate must serve all devices normally and allow critical devices to regain service after any one AP fails. All functioning APs stay on, and recovery can change the surviving APs' settings when reassignment alone is insufficient.

In our small synthetic shelter example, the all-high configuration used 16 Wh over one hour, while both the greedy baseline and annealing with recovery found configurations using 8 Wh. The annealing comparison that required surviving settings to remain unchanged after a failure found a 12 Wh configuration. These results help illustrate the difference between preparing enough coverage in advance and allowing settings to change during recovery, although we still need larger scenarios before drawing conclusions about which algorithm performs better. The project now has 48 passing tests covering the simulation and search, including checks that rejected moves still count toward the search limit and that annealing preserves its best configuration after accepting a worse move. The next step is to connect these results to the scenario loader and interface so that the application can display the selected settings and recovery behavior.
